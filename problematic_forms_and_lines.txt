Problematic Forms And Lines Audit
Generated: 2026-03-15

Scope
- This is a best-effort audit of the current federal 2025 model.
- "Problematic" means one or more of the following:
  1. Compatibility-only wiring because the internal line map still differs from the printed form.
  2. Manual/scaffold logic instead of full line-by-line form logic.
  3. Partial form logic that handles common cases but not all IRS branches.
  4. Missing form dependencies that make downstream lines unreliable for a full return.

Model-wide concerns
- The project still uses some internal compatibility line mappings on Form 1040 and related schedules rather than a perfect printed-form line map.
- Several newly added common forms exist only as output scaffolds. They can carry values, but they are not yet complete line-by-line reconstructions.
- Some core calculations still depend on manual helper values rather than fully derived facts.

f4952
- form-level issue: a first-pass scaffold now exists, but the hard classification, carryforward, sourcing, and election logic is still largely manual.
- carryforward issue: the model now has a generic `carryforward_records` block and `f4952.2` now reads from it before falling back to the old compatibility fact field, but there is still no automatic prior-year import/export workflow.
- filing-threshold issue: the model now has a `filing_exception_met` helper, but it is still only a partial implementation of the “you may not need to file Form 4952” exception because the underlying classification and carryforward logic are still incomplete.
- line 1 / allocation issue: line 1 now pulls from an `investment_interest_expense` source block, but the block assumes the user has already done the required allocation of mixed-purpose debt between investment, personal, business, home-mortgage, and passive buckets.
- line 1 / exclusions issue: the model does not yet exclude passive-activity interest, capitalized interest, tax-exempt-income interest, or other disallowed categories from investment interest expense.
- line 2 / carryforward issue: line 2 now pulls from a prior-year carryforward fact on the Federal Information Worksheet, but there is still no true cross-year rollover path yet.
- line 4a issue: line 4a now combines obvious 1099 interest / ordinary-dividend income with a manual adjustment bucket, but it is still not a complete synthesis of investment income. It can also include K-1 investment income, estate/trust investment income, some publicly traded partnership passive income, and certain recharacterized passive income.
- line 4a / classification issue: the model does not yet have a robust way to decide whether an income-producing asset or disposition belongs in “property held for investment” rather than business, passive, or personal categories.
- line 4d / 4e issue: lines 4d and 4e now pull from an `investment_property_dispositions` block plus helper adjustments, but the model still does not classify Schedule D activity into the Form 4952 investment-property subset on its own.
- line 4g election issue: line 4g now has explicit election-detail fields for the portions attributed to line 4e and line 4b, but the filing-timing, revocation, and optimization rules are not modeled. This election changes Schedule D Tax Worksheet line 3 and can also change how tax is optimized when Form 1116 is involved.
- line 4g attribution issue: the scaffold now captures separate elected amounts from line 4e and line 4b, but it still does not fully enforce the instruction-level attribution constraints and alternate-election nuances.
- line 5 issue: line 5 now pulls from an `investment_expenses` source block, but the model still does not determine on its own which expenses are allowed here, and the exclusion of suspended miscellaneous itemized deductions remains a source-modeling concern.
- line 7 / 8 issue: lines 7 and 8 are now computed, but they are only as reliable as the still-partial sourcing and classification on lines 1 through 6.
- publication-dependency issue: Pub. 550 supplies essential definitions and edge cases for investment interest, investment income, child income reported on Form 8814, bond-premium interactions, and passive-activity exclusions. These rules are not fully recoverable from the printed Form 4952 layout by itself.

f4952 build checklist
1. Add `f4952` with full line structure (`1`, `2`, `3`, `4a`-`4h`, `5`, `6`, `7`, `8`) and wire line `8` to `f1040sa.9`.
2. Add a prior-year carryforward storage path so Form `4952` line `7` can roll into next year's line `2`.
3. Add source buckets for debt/interest facts, separating investment interest from personal, passive, home-mortgage, business, capitalized, and tax-exempt-income-related interest.
4. Add source buckets or helper forms for non-interest investment expenses allowed on line `5`.
5. Add investment-income classification helpers so interest, ordinary dividends, K-1 investment income, estate/trust investment income, Form `8814` carry-ins, and allowed passive recharacterizations can feed line `4a`.
6. Add investment-property disposition helpers so only gains and losses from property held for investment feed lines `4d` and `4e`, including capital gain distributions and capital loss carryovers where the instructions require them.
7. Add a user-controlled election field for line `4g`, plus the default attribution rule that treats the election as coming first from line `4e` and then from line `4b`.
8. Add the alternate attribution election for line `4g` when the taxpayer wants less of line `4e` treated as elected and more of line `4b` treated as elected, as allowed by the instructions.
9. Implement the “exception to use of Form 4952” gate so the form can stay inactive when the IRS filing exception is met.
10. Rewire `f1040sd_Schedule_D_Tax` lines `3` and `4` to `f4952.4g` and `f4952.4e` logic instead of manual placeholders.
11. Validate the final model against both `Form 4952` and `Pub. 550`, because the publication defines key concepts the line layout does not.

Why the missing forms matter
- Missing `f1040sh` leaves household-employment tax reporting unresolved even though `f1040s2` already references Schedule H on line `9`.
- Missing `f1040sr`, `f1040sj`, and `f1040sr_schedule_r` leaves senior, farm-income averaging, and elderly/disabled credit filing paths incomplete.
- Missing `f1040es`, `f1040v`, and `f1040x` leaves payment-voucher, estimated-tax, and amended-return workflows outside the current model.
- Incomplete `f1116` limits confidence in foreign tax credit handling.
- Incomplete `f2210` limits underpayment penalty handling.
- Incomplete `f4952` still limits confidence in Schedule A investment-interest deductions and the linked Schedule D Tax Worksheet lines, because the remaining logic extends beyond the form face into Pub. 550 election, classification, carryforward, and exclusion rules.
- Incomplete `f1116` still limits confidence in foreign tax credit limitation, carryovers, and category-specific handling.
- Incomplete `f2210` still limits confidence in estimated-tax-penalty computation, especially when waiver or annualized-income methods apply.
- Missing `f8960` leaves net investment income tax unresolved.
- Missing `f5329` leaves many retirement-account additional-tax branches unresolved.
- Missing `f1040sc`, `f1040se`, and `f1040sf` block reliable business / rental / farm return support.
- Missing `f8824` leaves known gaps in Schedule D line 4 and line 11 sourcing.

Section D. Source-data and rule gaps that still affect downstream reliability

- No `1095-A` source block is currently modeled, even though Form 8962 normally depends on it.
- Schedule EIC child qualification is not yet fully derived from dependent facts.
- Earned income synthesis for Schedule 8812 is not yet complete.
- Some withholding sources are preserved but not fully routed in all edge cases.
- Some worksheets still rely on current master-model compatibility numbering rather than clean printed-form line identities.

Bottom line
- The current app can support many partial calculations and data-entry flows.
- It is not yet reliable for a full real-world return without manual review because of the line issues, scaffolded forms, and missing forms listed above.
